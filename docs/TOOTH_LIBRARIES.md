# Tooth libraries

OcclusaCAD designs crowns and pontics from a **tooth library**: one model tooth per position, scaled and adapted to the case.

## Built-in libraries

Three libraries are generated by OcclusaCAD itself (`core/crown/AnatomyGenerator`). They contain no third-party data.

| Id | Name | Character |
|---|---|---|
| `occlusacad-natural` (default) | OcclusaCAD Natural | Average adult anatomy with clear cusps, ridges and grooves |
| `occlusacad-young` | OcclusaCAD Young | Pronounced cusps, deep fissures, rounder outlines |
| `occlusacad-mature` | OcclusaCAD Mature | Worn anatomy: low cusps, wide occlusal tables, flat incisal edges |

Each library has all 14 tooth types (upper and lower, central incisor to second molar). Third molars use the second-molar shape.

Each tooth is described by:
- its outline: superellipse with direction-dependent modulation;
- its heights of contour, buccal/lingual and proximal;
- the occlusal table, or the incisal edge for incisors;
- relief features: cusps (broad rounded cones), triangular and marginal ridges, the oblique ridge of upper molars, cusp ridges of canines, grooves and pits, and the lingual fossa of anterior teeth.

The three styles vary cusp height, fissure depth, table width and outline roundness.

Export them to look at or edit:

```bash
occlusa_toothlib list
occlusa_toothlib export --library occlusacad-natural --out natural/     # 14 STL + library.json
occlusa_toothlib preview --library occlusacad-young --out young.stl     # all teeth side by side
```

## Library folders

A library is a folder with one STL per tooth and a `library.json`:

```json
{
  "format": "occlusacad.toothlibrary",
  "version": 1,
  "id": "lab-natural",
  "name": "Lab Natural",
  "author": "Riverside Dental Lab",
  "license": "Internal use",
  "description": "Scanned natural teeth",
  "teeth": [
    { "fdi": 16, "file": "16.stl",
      "origin": [0, 0, 0], "mesial": [1, 0, 0], "buccal": [0, 1, 0], "occlusal": [0, 0, 1],
      "cervicalZ": 0.0 }
  ]
}
```

* **Teeth**: one closed STL per position and jaw. The other side of the jaw uses the same tooth, because the tooth frame is anatomical (mesial/buccal), so left and right teeth share it. Missing positions fall back to the default library.
* **Tooth frame**: x points mesially, y buccally (labially), z occlusally. The origin is on the tooth's long axis at the cervical line.
  * If the STL is not already in this frame, give its frame in file coordinates with `origin`, `mesial`, `buccal` and `occlusal`. For example, for teeth exported in place from an arch.
  * `cervicalZ` is the height of the cervical line in the tooth frame. It defaults to the lowest point.
* **Shape requirements**: only the crown matters, from the height of contour over the occlusal surface. It must be star-shaped from a point about halfway up the axis, which natural crowns are.

`occlusa_toothlib create --in <folder> --name "Lab Natural" [--author ..] [--license ..]` writes the manifest for a folder of STLs named by FDI number (`11.stl`, `36.stl`, …) that are already in the tooth frame. It then prints every tooth's dimensions. `occlusa_toothlib info --in <folder>` checks an existing library.

## Using libraries in OcclusaCAD

* **Where libraries are found**: the designer loads every library folder in `<data folder>/libraries/`, which the whole lab shares. It also loads the user's own folder, `libraries/` next to the configuration file.
* **Importing**: **Import library…** on the Crown card copies a folder into the lab's libraries. Without a `library.json`, the folder is accepted when its STL files are named by FDI number and are in the tooth frame. Every tooth is checked before the library is offered.
* **Choosing**: the library is chosen per restoration on the Crown card, and saved with the design. Its author and license are shown under the selector.
* **Licensing**: OcclusaCAD does not redistribute imported libraries. Make sure the lab may use a library it imports. Commercial CAD libraries are usually licensed to one installation, and research datasets such as Teeth3DS are non-commercial.

## How library teeth become crowns

`sampleToothShape` resamples a library tooth into 144 azimuthal profiles. Each profile runs in the (radius, height) half-plane from the height of contour, over the occlusal surface, to the axis. The profiles are found by ray casting from a point on the axis.

The crown builder then works profile by profile:
1. **Scaling**: it scales the profiles anisotropically to the crown's mesial, distal, buccal, lingual and height dimensions. It picks the library azimuth that lands on each column after scaling.
2. **Joining the margin**: it joins each profile to the margin with the emergence-profile curve.
3. **Cusp height**: the cusp-height slider scales the relief around the tooth's occlusal level.

Margin adaptation, the minimum thickness, contacts and free-form editing then work the same for every library. The result is always a closed solid.
