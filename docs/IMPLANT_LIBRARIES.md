# Implant libraries and custom abutments

OcclusaCAD designs custom abutments on an **implant library**. A library connection gives:
- the interface to the implant, which is milled exactly as given;
- the scan body used to find the implant in the scan.

The implant system is chosen in OcclusaCAD, not in OcclusaCAD DB. The case only says that a tooth gets a custom abutment.

## The workflow

The "Custom abutment" workflow runs: Load data → **Scan body alignment** → **Abutment design** → Review & save.

### Scan body alignment

1. **Choose implant…** opens the library picker.
   * The libraries are listed as a tree: manufacturer, then implant system, then connection/platform. A search box filters it.
   * The right side shows the selected connection: its platform, the interface's top circle, the screw channel, the minimum wall, and which optional geometry the library provides.
   * **Import library…** installs a library folder.
2. **Click on the top of the scan body** in the scan. The library scan body is placed there along the surface normal in 12 rotations about its axis, and each placement is refined by ICP against the scan around the click. The best fit wins. The fit is reported as RMS and as the share of the scan body within 0.05 mm of the scan. A poor fit gives a warning: check the implant system and the scan.
3. **Refine** runs ICP again from the current position. **Clear** removes the position.

The implant position is stored in the coordinates of the scan, so it stays valid when the scan is later aligned to a CBCT.

### Abutment design

The abutment is built on the top circle of the library interface and is never allowed to change the interface.

* **Emergence profile**: a smooth surface from the interface's top circle up to the margin. Two rings of control points shape it.
  * **9 margin points** (orange), evenly spaced around the implant. Each one moves in radius and height.
  * **9 mid points** (blue), halfway between the interface and the margin. Each one moves along the normal of the straight line from the interface to its margin point. It controls whether the emergence profile is convex or concave there.
  * Between the control points the surface follows a closed spline, so it is smooth all the way round.
  * The default margin circle is 0.5 mm wider (in diameter) than the interface's top circle, with a straight (conical) emergence. Its height follows the gingiva: it sits 0.5 mm below the gingiva at each control point. **Fit to gingiva** repeats this with any depth.
* **Core** (the top cap the crown sits on): it rises from the shoulder inside the margin.
  * While **Follows the margin** is on, its outline follows the 9 margin points. Shoulder width, core height above the margin and taper are then set with sliders, and the core never gets thinner than the minimum wall.
  * Unlock it to drag each of its 9 points (green) on its own.
* **Screw channel**: straight along the implant axis, with an adjustable diameter. If the library provides a screw channel solid, it is removed as well.
* **Editing**:
  * Drag a point in the 3D view. It moves in the plane through the implant axis at its azimuth.
  * Hold **Shift** to move the whole ring.
  * The sliders change all points of a ring together.
  * **Undo** and **Reset** restore earlier shapes.
* **Checks**:
  * the thinnest wall around the screw channel against the library's minimum (shown as a colour map: red is too thin, yellow close to it);
  * a core with an undercut;
  * the library's minimum-thickness solid not covered;
  * the abutment not fitting inside the blank.
* **Display**: the scan is shown without the scanned scan body, which would hide the abutment. Its opacity can be changed.

### Export

On save, each abutment is exported as `design/abutment_<tooth>.stl`, in the configured tooth numbering. The file holds the designed part united with the unchanged interface (Manifold boolean), in the coordinates of the scan. Its STL header names the tooth in both numbering systems and the implant system. If the library interface is not a closed solid, the two parts are written side by side and a warning is shown.

## Built-in library

`occlusacad-generic` ("OcclusaCAD Generic") is generated by OcclusaCAD and contains no third-party data. It is a test library for an internal-hex connection, **not a real implant system**. It has three platforms: NP 3.5, RP 4.1 and WP 5.0.

| Part | Geometry |
|---|---|
| Interface | collar of the platform diameter, 0.6 mm high, on a hexagon going 1.4 mm into the implant, with a screw seat |
| Scan body | Ø 4.0 mm cylinder, 10 mm high, with a chamfered top and one flat (anti-rotation) |

## The OcclusaCAD library format

A library is a folder with a `library.json` and STL files:

```json
{
  "format": "occlusacad.implantlibrary",
  "version": 1,
  "id": "lab-conical",
  "name": "Lab Conical",
  "manufacturer": "Example Implants",
  "author": "Riverside Dental Lab",
  "license": "Internal use",
  "description": "Conical connection, two platforms",
  "connections": [
    { "id": "rp41", "name": "RP 4.1", "system": "Conical", "platformDiameter": 4.1,
      "interface": "rp41/interface.stl", "scanBody": "rp41/scanbody.stl",
      "screwChannel": "rp41/screwchannel.stl", "minThickness": "rp41/minthickness.stl", "blank": "rp41/blank.stl",
      "screwChannelDiameter": 2.4, "minWall": 0.4,
      "interfaceTop": { "height": 0.6, "diameter": 4.1 } }
  ]
}
```

* **Implant frame**: all meshes of a connection share one frame. The origin is at the implant platform on the implant axis, and +z points along the axis out of the implant (coronally). Rotation about the axis is whatever the library uses; the scan body and the interface just have to agree.
* **Required**: `interface` (a closed solid, so it can be united with the designed part) and `scanBody`.
* **Optional**: `screwChannel`, `minThickness` and `blank` (closed solids).
  * `screwChannelDiameter` is the default diameter of the straight channel. The default is 2.4 mm.
  * `minWall` is the minimum wall thickness. The default is 0.4 mm.
* **Interface top**: the abutment starts from the interface's top circle, which is measured from the mesh: its highest level and the outer radius there. `interfaceTop` overrides the measurement.

### Where libraries are found and how to install them

* **Search locations**: the designer loads every library folder in `<data folder>/implant-libraries/`, which the whole lab shares. It also loads the user's own `implant-libraries/` next to the configuration file.
* **Installing**: **Import library…** in the picker checks a folder and copies it into the lab's implant libraries.

### occlusa_implantlib

```bash
occlusa_implantlib list                                        # libraries and connections (top circle, geometry)
occlusa_implantlib export --library occlusacad-generic --out lab-generic --id lab-generic --name "Lab Generic"
occlusa_implantlib info --in lab-generic                       # check a library folder
```

## exocad and 3Shape libraries (planned)

Unencrypted exocad implant libraries and 3Shape implant libraries will be read directly.

* **3Shape**: a `.dcm` container (zip) with XML and DCM meshes. Libraries whose meshes are encrypted are rejected.
* **Orientation**: both formats ship their meshes already in the implant frame. A library whose meshes are not consistently oriented is invalid and is not repaired.

**Licensing**: OcclusaCAD does not redistribute imported libraries. Make sure the lab may use a manufacturer's library in OcclusaCAD.
